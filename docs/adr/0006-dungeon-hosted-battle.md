# ADR 0006：固定副本维度与战斗 Host 抽象

## 状态

已接受

## 背景

副本需要允许队伍在场景中自由探索，只在敌人警戒、敌方先手或玩家主动攻击时进入自走棋战斗。战斗必须继续复用既有 `BattleSession`、技能卡、HUD 和结算规则，同时不能把玩家切换到独立战斗维度，也不能清除或重铺副本房间。

## 决策

- 所有副本运行使用固定的 `exworld:dungeon` 维度。
- 每个队伍分配独立的 512×512 坐标槽位；槽位只由副本系统生成、加载和清理。
- `EncounterRequest` 携带 `BattleHost`，描述承载维度、战术区域原点、地面高度、是否由战斗系统拥有场景，以及副本运行/房间关联。
- 旧的 Fight Debug 和没有显式 Host 的遭遇继续使用 `exworld:battle` 与原有战斗场地清理逻辑。
- 副本 Host 将战斗逻辑区域放在当前房间内；战斗系统只使用逻辑障碍，不拥有副本方块。

## 后果

副本和战斗共享同一个服务端会话模型，战斗快照也能在服务器重启后恢复其维度与坐标。副本系统需要单独维护槽位、房间实体、区块加载和运行清理；战斗系统则必须始终通过 Host 解析实体和维度，不能再假设所有会话都在独立战斗维度。
