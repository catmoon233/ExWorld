# ADR 0007：战斗物品使用复用原版 Inventory，装备槽只保存物品 ID

## 状态

已接受。

## 决策

战斗消耗品直接读取并修改玩家服务端原版 `Inventory`。客户端只提交库存槽位、物品 ID 和目标格，`BattleItemAdapter` 在服务端重新验证真实 `ItemStack`；成功后立即扣除一个物品并标记库存变化。

消耗品仍直接读取并修改真实堆叠，不建立战斗背包副本。武器横槽持有真实 ItemStack；主动装备是主武器槽物品。切换武器把该槽堆叠投影到主手以供战斗表现，不再用物品 ID 在背包里查找并交换。

## 原因

原版 `Inventory` 是玩家实际拥有物品的唯一事实来源，避免战斗副本与世界背包产生双写、回滚和重连冲突。武器横槽成为装备事实来源，避免 ID 配置与真实堆叠漂移。

## 后果

- 成功的消耗品使用和主手交换不会在战斗结束时回滚。
- 未适配物品可以展示，但必须由白名单适配器明确启用后才可使用。
- 战斗快照按物品所属玩家过滤 `items` 和 `weaponSlots`，敌人及其他玩家不会获得真实库存投影。
- 物品适配器和武器被动采用代码注册 seam，未来可以分别扩展而不改变 `BattleSession` 命令模型。
- 武器物品是被动载体，不承载被动实现；`WeaponDefinition` 将物品 ID 与独立 `WeaponPassive` 关联。消耗品行为同样由 `BattleItemAdapter` 注册，允许 Minecraft 原版物品和 ExWorld 自定义物品共享同一战斗命令。
