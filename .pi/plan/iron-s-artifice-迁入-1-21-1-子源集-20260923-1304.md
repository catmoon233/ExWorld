# 把 Iron's Artifice 移植到当前 1.21.1 NeoForge 子源集

## 目标

在当前仓库新建 `irons_artifice/`，按 `lotm/` 的方式接进现有 NeoForge `21.1.248` / Minecraft `1.21.1` / Java 21 构建。源只读 `res/irons-artifice/irons-artifice-26.1.2-1.0.0`（与 `irons-artifice-main` 文件集和大小一致）。`res/irons-artifice` 本身不改、不删。

包名保持 `io.redspace.irons_artifice`，`modId` 保持 `irons_artifice`。许可保持上游 `All Rights Reserved`，不并进 ExWorld 的 GPL 源码，也不重新授权。

这不是逐字节覆盖。26.1.2 / Java 25 / GeckoLib 5 的源码在 1.21.1 上无法编译；同名文件会保留相对路径和玩法含义，只改对不上的 API。

## 放置位置

当前没有 `irons_artifice/`，没有同名冲突。

```
irons_artifice/src/main/java/io/redspace/irons_artifice/**   # 219 个 Java，包路径不变
irons_artifice/src/main/resources/**                       # 资源、mixin、enumextensions、音效贴图
irons_artifice/src/generated/resources/data/**             # 1.21.1 仍可用的配方、进度、战利品、标签
```

`mods.toml` 写成静态文件（与 `lotm` 一样），避免根工程的 `${mod_id}` 展开成 `exworld`。依赖声明为 NeoForge `[21,)`、Minecraft `[1.21.1,1.22)`、已有的 1.21.1 GeckoLib。不依赖 ExWorld。

## 现有文件只改两处

- `build.gradle`：增加 `sourceSets.irons_artifice`、`neoForge.mods.irons_artifice`、`loadedMods`、`prepareClientRun` 依赖、`ironsArtificeJar`。不改 ExWorld / lotm 的玩法源码。
- `THIRD_PARTY_NOTICES.md`：加一行，说明该子源集是 Iron's Arms 'n Artifice 的本地 1.21.1 移植，许可仍为 All Rights Reserved，不重新分发授权。

不新增 GeckoLib 5.5.2，也不新增 26.1 的 `irons_lib`。上游 `build.gradle` 里 `irons_lib` 已被注释，Java 侧也未引用。复用根工程已有的 `curse.maven:geckolib-388172:8350073`。

## 必须改写的 API

保持文件名和玩法含义，编译期按 1.21.1 映射修正：

- `net.minecraft.resources.Identifier` 改为 `ResourceLocation`。`fromNamespaceAndPath` / `withDefaultNamespace` 在 1.21.1 可用。
- GeckoLib 5 的 `com.geckolib.*`（`GeoRenderState`、`RenderPassInfo`、`SubmitNodeCollector` 渲染回调）改为 1.21.1 GeckoLib 4 的 `software.bernie.geckolib.*`，并用 `PoseStack` + `MultiBufferSource` 画第一人称枪、附件和帽子。涉及 `GunInHandRenderer`、`AttachmentGeoRenderer`、`SimpleItemGeoModel`、`GenericArmorModel`、`IronsArtificeClient`。
- 实体渲染从 26.1 的 `submit(RenderState, SubmitNodeCollector, CameraRenderState)` 改回 1.21.1 的 `EntityRenderer.render(entity, yaw, partialTick, PoseStack, MultiBufferSource, light)`。`ChainEntityRenderer`、`GunslingerRenderer`、`IllificerRenderer` 走这条。
- `DeferredRegister.Entities.registerEntityType` 改为 21.1 的 `DeferredRegister.create(Registries.ENTITY_TYPE, MODID)` + `EntityType.Builder`。
- `assets/irons_artifice/items/*.json` 是 1.21.4+ 物品定义，1.21.1 不读。改写成 `models/item`。`gun_display.json` / `pistol_display.json` 去掉 1.21.1 没有的 `on_shelf`。枪仍用 `builtin/entity`，由 GeckoLib 画。
- 枚举扩展保留。1.21.1 的 `HumanoidModel.ArmPose` 构造是 `(boolean, IArmPoseTransformer)`，不是 26.1 的 `(boolean, boolean, IArmPoseTransformer)`。`enumextensions.json` 和 `GunArmPoses` 按 21.1 构造改。`Raid.RaiderType` 若构造签名不同，只改扩展 JSON，不改 Illificer 行为。
- 网络包、数据组件、Attachment、配方/进度/标签 JSON 先原样迁入；编译报错再按 21.1 的 `IPayloadContext`、`DataComponentType`、`AttachmentType` 修，不改包语义。

## 明确不移植

- `SpearAnimationsMixin`、`KineticWeapon`、`BayonetAnimations.fromKineticWeapon`：1.21.1 没有矛和动能武器组件。刺刀伤害保留在对应 modifier 里；第一人称刺刀动作改成普通 `PoseStack` 挥击，不伪造矛组件。`GunCriteria` 里检查 `DataComponents.KINETIC_WEAPON` 的分支删掉。
- 上游独立工程文件：`gradlew*`、`gradle/wrapper`、`.github`、`settings.gradle`、`publishMods`、两个 zip。它们属于 26.1 发布工程，不是这个 1.21.1 子源集的对应物。
- `.bbmodel` 可随资源留下，但 jar 排除，与上游一致。
- 不改 `src/`、`lotm/`、`res/` 里与接线无关的文件。

## 校验

- 跑 `compileIronsArtificeJava`（source set 生成的编译任务）直到通过。
- 确认 `processIronsArtificeResources` 带上 `neoforge.mods.toml`、`irons_artifice.mixins.json`、`META-INF/enumextensions.json`。
- 不跑完整客户端；编译通过后列出已移植、已改写、未移植及原因。
- 若某一处 21.1 映射和预期不一致，停在该符号，不猜一个能编译但改变射击/装弹语义的替代实现。
